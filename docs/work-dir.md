# Рабочая папка и что остаётся на диске

Всё, что пишет review-agent, лежит в `storage.work_dir` (по умолчанию
`./.review-agent` относительно текущей папки процесса). Единственное
исключение — отчёт ручного режима, который пишется в `report.output_path`
(в примерном конфиге — `./reports/review-{run_id}.md`). Эти отчёты
review-agent не удаляет никогда.

```
<work_dir>/
  poll.lock                      пока идёт прогон; потом удаляется
  tmp/                           временное — пусто после каждого прохода
    <run_id>/                    worktree, prompt.md, safety-note.md, report.md, harness-stderr.log
    mr-<время>-<проект>-<iid>/   тела запросов в GitLab (claim, отчёт)
  logs/
    poll-<время>-<pid>.log                       лог каждого прохода poll
    <время>-<проект>-<iid>.harness-stderr.log    stderr харнесса упавшего ревью
  dry-run/<время>-<проект>-<iid>.comment.md      несостоявшийся комментарий --dry-run
  debug/<время>-<проект>-<iid>/                  всё из tmp/ (кроме worktree) при --debug
  debug/<время>-manual-<sha12>/                  то же для ручного режима
  repos/                                         кэш-клоны проектов без local_repo
    <проект>-<хэш8>.git/                         bare-клон + метка review-agent-last-used
    .incoming-<id>/                              клон в процессе (только во время прохода)
  usage/                                         учёт расхода — не удаляется никогда
    ledger.jsonl                                 одна запись на каждый прогон ревью
    price-catalog.json                           последняя загруженная копия справочника цен
```

## Что и когда удаляется

| Что | Когда удаляется |
| --- | --- |
| `tmp/<run_id>/`, `tmp/mr-…/` | сразу после каждого MR или ручного прогона, успешного или нет. После прохода `tmp/` пуст |
| отчёт `poll` | локально не хранится: он уже в GitLab (кроме `--dry-run` и `--debug`) |
| `logs/`, `dry-run/`, `debug/` | в начале каждого прохода `poll` — всё старше `storage.retention_days` (7 дней; `null` — не удалять). Число удалённых пишется в лог |
| `repos/<проект>.git` | в начале прохода, если кэш-клон не использовался `storage.repo_retention_days` (30 дней; `null` — не удалять) |
| `usage/` | никогда. Журнал маленький (~1–2 КБ на ревью). Начать заново — удалить `ledger.jsonl` вручную |
| `poll.lock` | в конце прогона, в том числе при ошибке; брошенный lock перехватывается следующим запуском |

- **Остатки прерванных прогонов** (процесс убит, машина выключена)
  удаляются в начале следующего прохода `poll`, под lock'ом. Сначала
  удаляются осиротевшие worktree в клонах включённых проектов и во всех
  кэш-клонах (`git worktree remove` + `prune`), затем всё содержимое
  `tmp/`, затем недокачанные (`.incoming-*`) и повреждённые кэш-клоны.
  Ручной прогон перед стартом убирает осиротевший worktree своего
  репозитория.
- Проход, который упёрся в lock, ничего не удаляет.
- `--debug` сохраняет файлы прогона в `debug/`. Следующий проход без
  `--debug` их не трогает, они уходят только по сроку хранения.
- Ошибка удаления (файл открыт другим процессом) — предупреждение в логе,
  проход продолжается.

## Что вне work_dir

Вне `work_dir` review-agent ничего не удаляет. Сам по себе не чистится:

- в вашем `local_repo` — объекты и `FETCH_HEAD`, которые приносит
  `git fetch` (обычные git-данные клона), и ref'ы
  `refs/remotes/<remote>/<target>`;
- профиль OpenCode пользователя: история сессий, логи, `opencode.db`
  (растёт примерно на 1,3 МБ за ревью, см. бэклог в AGENTS.md);
- отчёты ручного режима в `report.output_path`.

Старые папки `.review-agent-scratch/` (от ранних версий) review-agent не
использует. Если они остались, удалите их вручную.
