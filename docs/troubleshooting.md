# Если что-то пошло не так

Первым делом смотрите лог прохода `<work_dir>/logs/poll-*.log` (у `poll`) или
вывод консоли (у ручного режима). Коды результата задачи Task Scheduler
(`0x1`, `0x41306`, `0x80070002`…) расшифрованы в
[scheduling.md](scheduling.md#как-следить-за-задачей).

## Ревью

### Отчёт пустой или подозрительно короткий

Отчёт короче `gitlab.min_report_chars` в `poll` не публикуется: MR получает
статус `failed`, claim снимается, stderr харнесса сохраняется в
`<work_dir>/logs/<время>-<проект>-<iid>.harness-stderr.log`. В ручном режиме
stderr не сохраняется. Повторите прогон с `--debug`: промпт, safety-note,
отчёт и `harness-stderr.log` останутся в `<work_dir>/debug/…`.

Что проверить:

- Модель ответила без вызовов инструментов, и отчёт выглядит как ответ на
  первую строку промпта → в `harness.command` промпт передаётся позиционным
  `"{prompt}"`, а не через `--file "{prompt_file}"`. Верните шаблон из
  `config.example.yaml` ([decisions.md](decisions.md#промпт-через---file)).
- В stderr — `Permission denied: shell` на нужных командах → шаблон из
  `safety.denied_bash_patterns` слишком широкий (например, `*test*`
  совпадает с путём, где есть «test»). Сузьте его.

### Ошибка или предупреждение шаблона промпта

Сначала проверьте шаблон отдельно: `review-agent prompt-check --project
<group/project> --show` ([prompt.md](prompt.md#review-agent-prompt-check)).

- `неизвестная переменная: X` → опечатка или переменной нет в
  [списке](prompt.md#переменные). Проход и ручной режим не начинаются (код 2).
- `синтаксическая ошибка (…, строка N)` → незакрытый `{% if %}`/`{% block %}`
  или фигурные скобки в тексте. Пример кода со скобками оберните в
  `{% raw %}…{% endraw %}`.
- `файл шаблона не найден` / `не найден подключаемый шаблон` → путь
  `prompt.template` считается от текущей папки процесса (у задачи Task
  Scheduler — `-WorkingDirectory`). `include` ищется рядом с шаблоном,
  встроенный родитель — `builtin/default.md.j2`.
- `шаблон не использует переменную X` → агент не получит это значение
  (например, без `base_sha` он не знает, с чем сравнивать). Добавьте
  `{{ X }}` в текст. Переменная только в условии `{% if %}` тоже считается
  неиспользованной.
- `файл skill не найден` → проверьте путь в `skills`.

### В `harness-stderr.log`: `external_directory … auto-rejecting`, `Read …skill… failed`

Известное ограничение: агент не может прочитать skill-файлы, потому что они
лежат вне worktree, а неинтерактивный OpenCode отклоняет запрос на чтение
вне рабочей папки. Ревью идёт дальше без skill'а. Исправления пока нет —
см. [configuration.md](configuration.md#skills); держите `skills: []`.

В интерактиве при предупреждениях спрашивается «Продолжить? [y/N]». Если
вопрос мешает, исправьте шаблон: флага, отключающего вопрос, нет. `poll
--all` при предупреждениях не останавливается.

### `Agent not found`

В `harness.command` нет `--standalone`
([decisions.md](decisions.md#opencode-run---standalone)).

### `Variant unavailable`

У модели нет вариантов reasoning effort (типично для локальных) → поставьте
`provider.reasoning_effort: null`.

### Русский текст в отчёте или логе — «кракозябры»

Откройте лог как UTF-8 (`Get-Content … -Encoding UTF8`). Если кракозябры в
самом отчёте — сообщите: review-agent декодирует вывод харнесса как UTF-8
([decisions.md](decisions.md#явная-кодировка-utf-8)).

### Ревью зависло и не завершается

Если ревью запущено из оболочки с перенаправленным stdin, убедитесь, что
используется актуальная версия: харнесс запускается без stdin
([decisions.md](decisions.md#харнесс-без-stdin)). Зависший проход под
планировщиком завершится по `-ExecutionTimeLimitHours`.

## Опрос GitLab

### Код 2, «прогон уже выполняется»

Идёт другой прогон из той же рабочей папки (проход по расписанию или
ручной). Дождитесь его завершения. Lock убитого процесса перехватывается
автоматически: если PID из `<work_dir>/poll.lock` не существует, lock
считается брошенным. Если всё же нужно вмешаться, удалите файл (путь есть в
сообщении об ошибке).

### Код 2 без `--all`: «интерактивный режим без консоли»

`poll` без `--all` запущен без консоли (Task Scheduler, CI, `< NUL`). Добавьте
`--all`.

### Код 2: «GitLab недоступен» / glab не авторизован

- VPN не поднят или хост недоступен — проверьте `glab api user --hostname <host>`.
- `glab` не авторизован: `glab auth login --hostname <host>`.
- Под задачей с `-RunWhetherLoggedOn` (S4U) нет доступа к keyring или VPN
  пользовательской сессии → используйте обычный режим
  ([scheduling.md](scheduling.md#режим-запуска)).

### MR не находится

- Ни один из `reviewers` проекта не назначен **ревьюером** MR (автор и
  assignee не считаются).
- MR — draft, а `review_drafts: false`.
- На MR уже есть наш маркер ревью (MR больше не ревьюится, даже после
  новых коммитов) — удалите комментарий бота, чтобы отревьюить заново.
- Проект `enabled: false`.
- MR закрыт или смёржен — для тестов есть `--include-closed`.

### В MR висит «⏳ AI-ревью … выполняется»

Проход был убит и не успел удалить claim. Ничего делать не нужно: через
`gitlab.claim_ttl_minutes` следующий проход удалит claim и возьмёт MR сам.
Если ждать не хочется, удалите этот комментарий в MR вручную.

### Пришло письмо с «⏳ … выполняется», а отчёта в письме нет

Так и задумано: GitLab шлёт письмо при создании комментария, а отчёт
появляется редактированием того же комментария. Смотрите отчёт в MR.

### Ошибка клонирования кэш-клона

MR получает `failed` с причиной, остальные продолжаются. Проверьте, что
`glab` авторизован и у его учётной записи есть доступ к проекту, а `glab`
поддерживает `glab auth git-credential` (glab 1.115.0+). Повреждённый или
недокачанный клон удаляется в начале следующего прохода автоматически.

### Предупреждение «не найден ref merge-requests/…/head»

GitLab удалил MR-ref (старые и закрытые MR). Это не ошибка: остальные ref'ы
подтянуты, движок попробует `git fetch <sha>` или найдёт коммиты в целевой
ветке.

## Учёт расхода

### `Предупреждение: Учёт расхода: неожиданный ответ opencode: …`

Изменился формат OpenCode. Ревью не затронуто, числа в записи — `null`.
Что делать — [usage-accounting.md](usage-accounting.md#если-opencode-ответил-не-так).

### «Сессия прогона не найдена» у всех прогонов

Добавьте `--standalone` в `usage.session_list_command`.

### В сводке `n/a` вместо цены

Модели нет в справочнике цен → добавьте её в `usage.price_overrides`.
«копия от …» в шапке значит, что сети не было и цены взяты из последней
сохранённой копии.

## Task Scheduler

### `running scripts is disabled`

`powershell -ExecutionPolicy Bypass -File .\scripts\register-task.ps1 ...`

### «pythonw.exe не найден рядом с …»

У Python, которому принадлежит `review-agent.exe`, нет `pythonw.exe` (редкие
сборки). Зарегистрируйте задачу с `-ShowConsole`.

### Задача не запускается, результат `0x80070002` / `0x8007010B`

Не найден `review-agent.exe` или рабочая папка → перерегистрируйте задачу с
правильными `-ReviewAgentPath` / `-WorkingDirectory`.

### Проходы наслаиваются или пропускаются

Пока проход идёт, второй экземпляр не запускается. Если длительность
прохода в логе приближается к интервалу, увеличьте `-IntervalMinutes`.
