# Запуск по расписанию (Windows Task Scheduler)

review-agent сам ничего не планирует: каждый вызов — один проход
`poll`. Периодически его вызывает Task Scheduler, задачу для которого
создаёт `scripts/register-task.ps1` (встроенный модуль `ScheduledTasks`,
ничего ставить не нужно).

Собирать exe не нужно. Задача запускает `review-agent.exe` из venv
проекта — маленький запускатель, который создаёт `pip install -e .`
(`.venv\Scripts\review-agent.exe`). Сборка в один бандл (PyInstaller и т.п.)
ничего не даёт: `git`, `opencode` и `glab` всё равно нужны на машине
отдельно, а однофайловые exe часто ловят ложные срабатывания антивируса.

## Установка, обновление, удаление

Из PowerShell в папке проекта, с активированным venv (тогда
`review-agent` найдётся в PATH сам):

```powershell
# 1. Сначала — расписание в режиме dry-run: ревью идут, в GitLab ничего не пишется
.\scripts\register-task.ps1 -DryRun -IntervalMinutes 15

# 2. Проверили логи — регистрируем боевую задачу (то же имя — задача обновляется)
.\scripts\register-task.ps1

# Удалить задачу
.\scripts\register-task.ps1 -Remove
```

Если PowerShell не даёт запускать скрипты (`running scripts is disabled`):
`powershell -ExecutionPolicy Bypass -File .\scripts\register-task.ps1 ...`.

Перед регистрацией скрипт проверяет, что существуют рабочая папка,
`review-agent.exe` и конфиг (путь к конфигу считается от рабочей папки), и
печатает итоговую команду задачи.

## Параметры

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `-TaskName` | `review-agent-poll` | имя задачи; повторный запуск с тем же именем обновляет её |
| `-IntervalMinutes` | `30` | интервал повтора, 1–1440 |
| `-ConfigPath` | `config.yaml` | конфиг (относительно рабочей папки) |
| `-WorkingDirectory` | папка проекта (родитель `scripts\`) | рабочая папка задачи; от неё считаются относительные пути конфига, включая `storage.work_dir` |
| `-ReviewAgentPath` | `review-agent` из PATH | путь к `review-agent.exe`, если venv не активирован: `<проект>\.venv\Scripts\review-agent.exe` |
| `-LogonDelayMinutes` | `5` | дополнительный проход через N минут после входа в Windows (0–240); `0` — не добавлять |
| `-ExecutionTimeLimitHours` | `4` | Task Scheduler завершит зависший проход (1–72). `gitlab.claim_ttl_minutes` должен быть не меньше |
| `-DryRun` | выкл. | `poll --all --dry-run` |
| `-DebugMode` | выкл. | `poll --all --debug` — сохранять артефакты прогонов в `debug/` |
| `-ShowConsole` | выкл. | показывать консольное окно во время прохода |
| `-RunWhetherLoggedOn` | выкл. | запускать и без входа пользователя (S4U), см. [Режим запуска](#режим-запуска) |
| `-Remove` | выкл. | удалить задачу (если её нет — не ошибка) |

Задача всегда запускает `poll --all` (без `--all` проход без консоли
отказывается работать) и никогда — с `--include-closed`. Пока проход идёт,
второй экземпляр не запускается («Не запускать новый экземпляр»).
Пропущенный интервал безвреден: MR возьмёт следующий проход.

## Окно

По умолчанию проход идёт **без консольного окна**: задача запускает
`pythonw.exe -m review_agent ...` того же Python, что и `review-agent.exe`
(в venv — `.venv\Scripts\pythonw.exe`, в обычной установке —
`Python310\pythonw.exe`). Окно не всплывает каждые N минут, и его нельзя
случайно закрыть. Код выхода 0/1/2 доходит до Планировщика как обычно.

С `-ShowConsole` задача запускает `review-agent.exe` напрямую, и проход
виден в окне. Это удобно для отладки, но окно не закрывайте: закрытие
обрывает проход (результат `0xC000013A`).

## Пропущенные проходы

В обычном режиме задача работает, только пока вы вошли в Windows. Проход,
пропущенный за это время, наверстывается: у задачи есть второй триггер
«при входе в систему» с задержкой `-LogonDelayMinutes` (по умолчанию 5
минут, чтобы успел подняться VPN) и флаг «запускать при первой
возможности, если плановый запуск пропущен».

## Режим запуска

- **Обычный (`Interactive`, по умолчанию, рекомендуется).** Задача
  работает, только пока вы вошли в Windows, и видит ваш профиль: токен
  `glab`, авторизацию OpenCode, VPN вашей сессии.
- **`-RunWhetherLoggedOn` (S4U).** Работает и без входа (пароль не
  хранится), но без сетевых кредов Windows. Если `glab` хранит токен в
  системном хранилище (`glab auth login --use-keyring`) или VPN поднимается
  только в пользовательской сессии, проход упадёт с «GitLab недоступен»
  (код 2, причина в логе). Под S4U проверено, что `glab` и VPN доступны,
  но вызов модели не проверялся. Используйте S4U только после одной
  проверки настоящим ревью.

## Как следить за задачей

Всё делается встроенными средствами Windows.

**Планировщик заданий** (`Win+R` → `taskschd.msc` → «Библиотека планировщика
заданий» → `review-agent-poll`):

- колонки «Состояние», «Время прошлого запуска», «Время следующего
  запуска», **«Результат последнего запуска»**:

  | Результат | Что значит |
  | --- | --- |
  | `Операция успешно завершена. (0x0)` | проход прошёл: всё опубликовано/пропущено или нечего ревьюить |
  | `(0x1)` | проход дошёл до конца, но какой-то MR или проект упал — причина в логе прохода |
  | `(0x2)` | проход не стартовал: GitLab/VPN недоступен, ошибка конфига или шаблона промпта, другой прогон уже идёт — причина в логе (предупреждения шаблона проход в `--all` не останавливают) |
  | `Задача выполняется. (0x41301)` | проход идёт прямо сейчас |
  | `(0x41306)` | проход прерван по лимиту времени (`-ExecutionTimeLimitHours`) или кнопкой «Завершить» |
  | `(0x41303)` | задача ещё ни разу не запускалась |
  | `(0xC000013A)` | проход оборван закрытием консольного окна (только с `-ShowConsole`) или Ctrl+C |
  | `(0x80070002)` / `(0x8007010B)` | Windows не нашла `review-agent.exe` или рабочую папку — перерегистрируйте задачу с правильными `-ReviewAgentPath` / `-WorkingDirectory` |

- вкладка **«Журнал»** — каждый запуск и завершение. Если она пуста,
  включите один раз: правая панель «Действия» → «Включить журнал всех
  заданий»;
- правая панель: **«Выполнить»** — запустить проход сейчас,
  **«Завершить»** — остановить идущий проход, «Отключить» — временно
  выключить расписание.

**Диспетчер задач** (`Ctrl+Shift+Esc` → «Подробности»): во время прохода
видны `pythonw.exe` (оркестратор; с `-ShowConsole` — `review-agent.exe` и
`python.exe`), `opencode` / `node.exe` (харнесс, основная нагрузка на CPU и
память), `git.exe`, `glab.exe`.

**Монитор ресурсов** (`Win+R` → `resmon`): диск и сеть тех же процессов
(обращения к GitLab и провайдеру модели). Отметьте процессы на вкладке
«ЦП», чтобы остальные вкладки показывали только их.

**Просмотр событий** (`Win+R` → `eventvwr.msc` → «Журналы приложений и
служб» → Microsoft → Windows → TaskScheduler → Operational): история
запусков, кодов завершения и причин, почему задача не стартовала.

**PowerShell:**

```powershell
Get-ScheduledTaskInfo -TaskName review-agent-poll   # LastRunTime, LastTaskResult (0/1/2), NextRunTime
Get-ScheduledTask -TaskName review-agent-poll | Select-Object -ExpandProperty Triggers   # интервал повтора
Get-ChildItem .\.review-agent\logs | Sort-Object LastWriteTime | Select-Object -Last 5   # последние логи
Get-Content (Get-ChildItem .\.review-agent\logs\poll-*.log | Sort-Object LastWriteTime | Select-Object -Last 1) -Encoding UTF8
```

**Что именно сделал проход** — только в логе прохода
`<work_dir>\logs\poll-*.log`: найденные MR, кто пропущен и почему, что
опубликовано, что упало, длительность. Если длительность прохода
приближается к интервалу, увеличьте `-IntervalMinutes`.
