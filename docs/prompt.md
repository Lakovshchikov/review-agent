# Промпт ревью

Агент получает методологию ревью одним прямым промптом на каждый прогон.
Промпт рендерится из Jinja2-шаблона. Встроенный шаблон
`builtin/default.md.j2` даёт проверенный базовый промпт, а проект может
указать свой файл. В конфиге хранится только путь к файлу, а не текст
([configuration.md](configuration.md#prompt)).

Содержание: [Какой шаблон действует](#какой-шаблон-действует) ·
[Переменные](#переменные) · [Встроенный шаблон и его блоки](#встроенный-шаблон-и-его-блоки) ·

## Какой шаблон действует

Каждый ключ секции `prompt` (`template`, `instruction_files`, `docs_dirs`)
берётся с самого верхнего уровня, где он задан:

```
prompt: проекта (gitlab.projects[])  ->  глобальная секция prompt:  ->  встроенное значение
```

Ручной режим (`review-agent --repo …`) использует глобальную секцию.
Шаблон загружается только из файла, указанного в конфиге, и из пакета
review-agent, и никогда — из ревьюируемого репозитория: его содержимое
контролирует автор MR.

`instruction_files` и `docs_dirs` — пути **внутри ревьюируемого
репозитория**. review-agent ищет первый существующий и передаёт агенту
путь к нему (переменные `repo_instructions_path`, `docs_path`). Содержимое
агент читает сам.

## Переменные

| Переменная | Тип | Значение |
| --- | --- | --- |
| `worktree_path` | путь | временная рабочая копия на head MR, где работает агент |
| `base_sha` | строка | базовый коммит MR; агент сравнивает с ним HEAD |
| `mr_title` | строка | заголовок MR, может быть пустым |
| `mr_description` | строка | описание MR, может быть пустым |
| `repo_instructions_path` | путь или пусто | первый найденный файл из `instruction_files` |
| `docs_path` | путь или пусто | первая найденная папка из `docs_dirs` |
| `skill_paths` | список путей | абсолютные пути к файлам `skills`, может быть пустым. Сейчас агент не может прочитать эти файлы — [известное ограничение](configuration.md#skills) |

Других переменных нет. Это минимальный контекст ревью: diff, список
файлов и размер MR агенту сознательно не передаются (AGENTS.md п.3–4).
Пустые значения обрабатывает сам шаблон, например
`{{ mr_title or "(не указан)" }}` или `{% if docs_path %}…{% endif %}`.

## Встроенный шаблон и его блоки

Файл — `src/review_agent/prompts/default.md.j2`. Его текст совпадает с
базовым промптом исследования посимвольно (это закреплено тестом). Текст
разбит на блоки, которые можно заменять по одному:

| Блок | Что в нём |
| --- | --- |
| `role` | `Role: Senior Software Engineer.` |
| `task` | задача: сравнить HEAD с `base_sha`, где лежит рабочая копия |
| `mr_context` | заголовок и описание MR |
| `repo_context` | пути к инструкциям и документации репозитория (если найдены) |
| `skills` | справочник skill'ов «как подсказка, не ограничение» (если есть) |
| `checklist` | что проверять: корректность, runtime-баги, читаемость, тестируемость, безопасность, SRP, контракты, лучшие практики |
| `severity` | SEV: Blocker / Major / Minor |
| `fix` | предложить минимальное исправление |
| `coverage` | не ограничиваться очевидным, искать как можно больше |
| `confidence` | допустимы находки с неполной уверенностью |
| `restrictions` | не изменять код, не запускать сборку, тесты и линтер |
| `output` | язык вывода |

## Свой шаблон

Целиком свой промпт — обычный текстовый файл с переменными:

```jinja
Ты ревьюишь изменения относительно {{ base_sha }} в {{ worktree_path }}.
{% if repo_instructions_path %}Сначала прочитай {{ repo_instructions_path }}.
{% endif %}…
```

Наследование встроенного шаблона с заменой одного блока — удобно для
другого стека, когда остальная методология подходит:

```jinja
{% extends "builtin/default.md.j2" %}
{% block checklist %}Проверь:
- корректность и транзакционные границы;
- N+1 и тяжёлые запросы;
- миграции БД и обратную совместимость API;
- безопасность и обработку ошибок.{% endblock %}
```

`{{ super() }}` внутри блока вставляет его встроенный текст: так можно
дополнить блок, а не заменить. Файлы, лежащие рядом с шаблоном,
подключаются через `{% include "common.md.j2" %}`.

Что важно знать:

- `{{ … }}` и `{% … %}` в тексте шаблона — синтаксис Jinja2. Пример кода с
  фигурными скобками оберните в `{% raw %}…{% endraw %}`.
- При наследовании ставьте `{% extends %}` **первой строкой**: текст и
  переводы строк перед ним попадают в начало промпта. После `extends`
  выводятся только блоки, так что комментарии `{# … #}` и пустые строки
  между блоками безопасны.
- Пробелы и переводы строк вокруг тегов попадают в промпт как есть.
  Посмотреть итоговый текст можно через `review-agent prompt-check --show`.
- В журнал расхода пишется путь шаблона и sha256 его файла
  ([usage-accounting.md](usage-accounting.md)). При `extends` или `include`
  хэшируется только сам файл, а не родитель.
- Встроенный промпт — проверенный baseline. Изменение методологии может
  снизить число находок, поэтому сравнивайте прогоны по журналу расхода.

## Проверка шаблонов

Шаблон проверяется пробным рендером с тестовыми значениями.

| Уровень | Что | Последствие |
| --- | --- | --- |
| ошибка | файл шаблона (или `include`/`extends`) не найден | работа не начинается |
| ошибка | синтаксическая ошибка Jinja2 | работа не начинается; на файл — одна, первая |
| ошибка | неизвестная переменная или атрибут (`{{ base_shaa }}`) | работа не начинается |
| предупреждение | шаблон не выводит одну из переменных, например `base_sha` | агент не получит это значение |
| предупреждение | файл из `skills` не найден | агент не сможет его прочитать |

Переменная, которая стоит только в условии (`{% if docs_path %}читай
документацию{% endif %}`) и не выводится в текст, считается
неиспользованной: агент её значения не получает.

Все замечания по всем шаблонам собираются за один раз и выводятся одним
списком, каждая строка помечена уровнем `ERROR` или `WARNING`:

```
Проверка шаблонов промпта:
  E:\prompts\frontend.md.j2  (web/front-checkout-admin-panel)
    ERROR   неизвестная переменная: base_shaa
    WARNING шаблон не использует переменную worktree_path — агент не получит это значение
Итого: ошибок 1, предупреждений 1.
```

Один и тот же шаблон проверяется один раз и отображается со всеми
проектами, которые его используют.

Когда проверка выполняется:

| Команда | Что проверяется | Ошибка | Только предупреждения |
| --- | --- | --- | --- |
| `poll` (интерактивно) | включённые проекты, до lock и GitLab | код 2, ничего не делается | один вопрос «Продолжить? [y/N]»; «нет» — код 2 |
| `poll --all` | включённые проекты | код 2 | пишутся в консоль и лог прохода, проход продолжается |
| `review-agent --repo …` | глобальные настройки, до создания worktree | код 2 | в консоли — вопрос; без консоли — stderr и продолжение |
| `prompt-check` | см. ниже | код 2 | код 1 |

## `review-agent prompt-check`

Проверяет шаблоны без ревью, без GitLab и без lock.

```bash
review-agent prompt-check [--project PATH | --template FILE] [--show] [--config config.yaml]
```

| Флаг | Что делает |
| --- | --- |
| (без флагов) | глобальные настройки и итоговые настройки каждого проекта, включая выключенные |
| `--project PATH` | только итоговые настройки проекта `PATH` (`group/project`) |
| `--template FILE` | отдельный файл шаблона, без проектов; skills — глобальные из конфига, если он загрузился |
| `--show` | дополнительно напечатать отрендеренный промпт с тестовыми значениями |
| `--config PATH` | конфиг, по умолчанию `config.yaml` |

Коды выхода: `0` — замечаний нет, `1` — только предупреждения, `2` — есть
ошибки, конфиг не загрузился или проект не найден.
