# Validation notes — review-usage-accounting

Машина автора: Windows 11, OpenCode v2.0.21, провайдер `openai` (подписка ChatGPT).

## 1.1 Образцы вывода OpenCode (2026-10-04)

Сняты на реальных сессиях, обезличены (весь текст → `<text …>` с сохранением
`ses_…`-ссылок, пути → `{worktree}`), лежат в `tests/fixtures/opencode/`:

- `review-session.json` — реальное ревью `b2c/front-shopping` (PLATCHCKT-762),
  `ses_f0344a877ffemdWd4lWd2BI520`;
- `subagent-parent.json` / `subagent-child.json` — короткий `opencode run`
  (gpt-5.6-luna#low) в пустом тестовом репозитории с просьбой запустить
  субагента через task;
- `session-list.txt` — формат `opencode session list` (`ses_<id>\t<заголовок>\t<дата>`);
- `version.txt` — `opencode v2.0.21`.

Ответы на вопросы design.md (решение 1):

1. **Связь родитель–ребёнок.** У дочерней сессии есть `info.parentID`; у
   родителя — часть `type: tool`, `name: "subagent"` с
   `state.metadata.sessionID = <id ребёнка>`. Дочерние сессии в
   `session list` не показываются. Поддерживаемая кодом форма
   «ссылка в сообщениях родителя + проверка `parentID` ребёнка» подтверждена.
   `info.tokens` родителя **не включает** токены ребёнка (12 484 против
   10 636 input) — суммирование по сессиям не даёт двойного счёта.
   `opencode stats` считает такую сессию субагентом (`subagents: 1`).
2. **Шаги** — сообщения `type: "assistant"`; у каждого свои `tokens` и
   `finish` (`tool-calls` / `stop`). В ревью-сессии их 9. Прочие типы
   сообщений: `user`, `agent-switched`, `idle`.
3. **Длительность сессии** — `time.idle − time.created`: в ревью-сессии
   155,1 с, а `time.updated − time.created` всего 2,8 с (`updated`
   выставляется в начале и дальше не меняется). Код берёт
   `max(updated, idle) − created`, что даёт то же.

Попутно: у сессии агента по умолчанию (`opencode run` без `--agent`) поля
`info.agent` нет — это не ошибка формата, агент просто `null`. Сумма
`tokens.input` по сообщениям ассистента родителя (11 943) немного меньше
`info.tokens.input` (12 484) — видимо, служебный вызов генерации заголовка;
источник правды — агрегат `info.tokens`.

Найдено тестом на реальном формате и исправлено: ошибка экспорта
*соседней* сессии из `session list` давала предупреждение о формате, даже
когда сессия прогона найдена. Теперь проблемы соседей учитываются только
если сессия прогона не найдена.

## 7.1 Живой интерактивный прогон (2026-10-04)

`review-agent poll --dry-run --include-closed` из консоли PowerShell, выбран
`b2c/front-shopping !511`, модель `openai/gpt-5.6-luna#low`. В GitLab ничего
не записано, отчёт — `.review-agent/dry-run/…-511.comment.md`.

- Вопросы о квоте заданы до и после ревью, ответы записаны в `review.quota`.
- Запись журнала совпала с `opencode session export ses_ef8ca625effeUdO20Q9nL1SBqy`:
  input 100 344 + cache read 31 232 = `gen_ai.usage.input_tokens` 131 576,
  output 1 909, reasoning 691, 6 шагов; сессия 79,2 с, весь прогон 80,3 с.
- Сессия найдена командой `opencode session list` **без** `--standalone` —
  значение по умолчанию подходит.
- Размер совпал с `git diff --shortstat` (22 файла, +222/−202, 4 коммита).
- Находки 0/1/2 совпали с отчётом (`### [Major]`, 2 × `### [Minor]`).
- Агент действительно исследовал код: 16 вызовов инструментов (6 shell —
  только read-only `git diff`/`git show`/`git status`, 4 grep, 6 read).

Проблемы формата: нет. Предупреждений: нет.

**Найдено по ходу и исправлено:** `opencode run`, запущенный с открытым
не-консольным stdin (так запускала моя оболочка; так же будет в CI),
висит, не создавая сессии (20+ минут, лимиты не тратились). Харнесс и
команды учёта теперь запускаются с `stdin=DEVNULL`. Из консоли и под Task
Scheduler (`< NUL`) этого не было видно. Повторный запуск из моей оболочки
после исправления завершился за 1,3 с ошибкой OpenCode `Agent not found:
"reviewer"`, а тот же код из консоли пользователя отработал — это
особенность запуска OpenCode из среды агента, а не review-agent; учёт при
этом записал корректную `failed`-запись.

**Замечание по вводу квоты:** в прогоне введено 100/100 до и после.
Работающий прогон при 100 % *использованного* лимита невозможен, так что
это, вероятно, *остаток* (UI Codex показывает оставшийся процент). Вопрос
просит «использовано» — см. п. о формулировке в ответе пользователю.

`python` → «3.10.11»); теперь — по `harness.command[0]`.

`PassLog.warning` (консоль + лог прохода) покрыт тестом
`test_drift_warning_reaches_console_once_per_pass`.

процент — вопрос переформулирован на «сколько % ОСТАЛОСЬ», в журнал
пишется `100 − остаток`. Запись прогона `!511` исправлена соответственно:
`before`/`after` = 0 % использовано по обоим окнам (ревью на luna/low не
сдвинуло округлённый процент).
