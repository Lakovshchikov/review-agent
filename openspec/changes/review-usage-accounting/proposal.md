# Proposal

## Why

Сейчас не видно, сколько стоит одно агентское ревью: OpenCode хранит
токены сессий у себя (`opencode.db`), но не связывает их с MR, размером
изменения и результатом ревью. Для подписки он не считает и цену
(`cost: 0`). Автору нужны цифры для обоснования перед работодателем:
сколько в среднем стоит ревью MR в API-эквиваленте, как это зависит от
размера MR и модели, какую долю лимитов подписки съедает ревью. Цифры
должны собираться автоматически по каждому прогону и в форме, которая
переживёт переезд в GitLab CI.

## What Changes

- После **каждого** прогона ревью (по расписанию, `poll --all`,
  интерактивного, ручного; успешного, упавшего или прерванного)
  review-agent собирает расход токенов у харнесса и пишет **одну запись
  в журнал расхода**: `<work_dir>/usage/ledger.jsonl`. Для OpenCode
  источник — `opencode session export`: агрегат сессии с полями fresh
  input, cache read/write, output, reasoning, модель, вариант, исход,
  время. Сессия находится по пути worktree прогона.
- **Субагентские (дочерние) сессии** прогона, если они есть,
  находятся рекурсивно. Их токены входят в итог, а разбивка по сессиям
  хранится в записи.
- **Время**: общее время прогона (измеряет оркестратор) и время каждой
  сессии.
- В записи также: проект, MR, base/head SHA, источник запуска
  (poll/manual), конфиг прогона (провайдер, модель, reasoning effort,
  skills), версия харнесса, **размер изменения** (файлы, +/- строки,
  коммиты), **число находок по SEV** из отчёта. Размер изменения
  оркестратор считает сам и агенту не передаёт: принцип «минимальной
  подготовки контекста» (AGENTS.md п.4) не нарушается.
- Имена полей записи следуют OpenTelemetry `gen_ai.*`, а свои поля
  лежат в пространстве `review.*`. Запись не зависит от провайдера.
- **Замер квоты подписки в интерактивном режиме.** Когда ревьюится ровно
  один MR из консоли (`poll` без `--all` или ручная команда), система
  спрашивает текущие проценты окон лимита (например, `5h` и `week`)
  перед ревью и после него. Enter пропускает вопрос. Измеренная пара
  пишется в запись этого ревью. В `--all` и по расписанию вопросов нет
  никогда. Автоматического получения процентов в этом change нет
  (см. «Вне объёма»).
- Новая команда **`review-agent usage`** — сводка по журналу за период:
  по ревью, MR, модели и дням. В сводке токены, время, размер,
  находки, **API-эквивалент в $** и **доля лимитов**: измеренная для
  ревью с замером, оценка по коэффициенту группы (провайдер, модель,
  effort) для остальных ревью той же группы. Вывод в виде таблицы, CSV
  или JSON.
- **Цены**: без ручных таблиц. Справочник цен LiteLLM загружается по URL
  **при каждом запуске `usage`**, то есть всегда актуальный. Если
  загрузка не удалась, используется последняя сохранённая копия с явным
  предупреждением и её датой. Переопределения в конфиге записываются в
  формате, совместимом со справочником, и имеют приоритет. Для модели
  без цены выводится «n/a», ошибки нет.
- **Изменение формата ответов OpenCode** (поля экспорта, строки списка
  сессий) или непроверенная версия OpenCode — это не ошибка, но **явное
  предупреждение в консоли и в логе прохода**. Ревью и код выхода не
  меняются. Причина пишется в запись, а сводка показывает, сколько
  записей за период затронуто.
- Сбор расхода никогда не ломает ревью.
- Не BREAKING: секция конфига `usage` необязательна.

**Вне объёма** (бэклог AGENTS.md п.7): автоматический замер % лимитов
подписки (прямой `wham/usage` с токеном OpenCode v2 отвечает 401;
кандидаты — debug-лог OpenCode или Codex CLI как харнесс), отправка
записей по OTLP, строка расхода в комментарии к MR, LiteLLM-шлюз для
этапа CI, выбор модели по размеру MR.

## Capabilities

### New Capabilities
- `review-usage-accounting`: учёт расхода ревью. Сбор токенов прогона и
  его субагентов у харнесса, журнал расхода с провайдер-нейтральной
  схемой записи, интерактивный замер квоты подписки, сводка с
  API-эквивалентом по актуальному справочнику цен и долей лимитов,
  явные предупреждения об изменении формата харнесса.

### Modified Capabilities
- `local-artifact-lifecycle`: в рабочей папке появляется область учёта
  расхода (журнал и сохранённая копия справочника цен). Уборка её не
  удаляет.

## Impact

- Код: `pipeline.py` (сбор расхода после harness, в том числе при
  ошибке; вопросы о квоте), `polling.py` (метки проекта/MR, признак
  интерактивного прогона одного MR), `cli.py` (подкоманда `usage`,
  интерактивный замер в ручной команде), `config.py` (секция `usage`),
  `housekeeping.py` (область `usage/`). Предупреждения о дрейфе формата
  идут через существующий `PassLog.warning`. Новые модули учёта: источник расхода, журнал, справочник
  цен, сводка.
- Внешние команды: дополнительно `opencode --version`, `opencode session
  list`, `opencode session export` (только чтение) после прогонов.
- Сеть: команда `usage` скачивает справочник цен (по умолчанию —
  публичный файл LiteLLM на GitHub). В прогонах ревью новых сетевых
  обращений нет.
- Данные: в журнал не попадают тексты промптов, отчётов и кода, только
  числа и идентификаторы.
- Документация: README (учёт расхода, замер квоты, сводка, цены),
  AGENTS.md (дорожная карта, команды разработки).
