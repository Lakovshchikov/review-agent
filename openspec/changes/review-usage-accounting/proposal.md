# Proposal

## Why

Сейчас не видно, сколько стоит одно агентское ревью: OpenCode хранит
токены сессий у себя (`opencode.db`), но не связывает их с MR, размером
изменения и результатом ревью. Для подписки он не считает и цену
(`cost: 0`). Автору нужны цифры для обоснования перед работодателем:
сколько в среднем стоит ревью MR в API-эквиваленте, как это зависит от
размера MR и модели, какую долю лимитов подписки съедает регулярное
ревью. Цифры должны собираться автоматически по каждому прогону и в
форме, которая переживёт переезд в GitLab CI.

## What Changes

- После каждого прогона ревью (успешного, упавшего или прерванного)
  review-agent **собирает расход токенов** этой сессии у харнесса и
  пишет **одну запись в журнал расхода**:
  `<work_dir>/usage/ledger.jsonl`. Для OpenCode источник —
  `opencode session export`: агрегат сессии с полями fresh input,
  cache read/write, output, reasoning, модель, вариант, исход и время.
  Сессия находится по пути worktree прогона.
- В записи также: проект, MR, base/head SHA, источник запуска
  (poll/manual), конфиг прогона (провайдер, модель, reasoning effort,
  skills), **размер изменения** (файлы, +/- строки, коммиты) и **число
  находок по SEV** из отчёта. Размер изменения оркестратор считает сам
  и агенту не передаёт: принцип «минимальной подготовки контекста»
  (AGENTS.md п.4) не нарушается.
- Имена полей записи следуют OpenTelemetry `gen_ai.*`, а свои поля
  лежат в пространстве `review.*`. Запись не зависит от провайдера:
  лимиты, цены и источник токенов подключаются отдельно.
- Новая команда **`review-agent quota note`** — ручная отметка
  процентов окон лимита подписки (например, `5h=23 week=41`). Она пишет
  запись в тот же журнал. Автоматического получения процентов в этом
  change нет (см. «Вне объёма»).
- Новая команда **`review-agent usage`** — сводка из журнала за период:
  по ревью, MR, модели и дням. В сводке токены, **API-эквивалент в $**
  по прайс-листу, а также **оценка % лимитов** через коэффициент,
  откалиброванный по ручным отметкам. Вывод в виде таблицы, CSV или
  JSON.
- **Прайс-лист** — справочные данные, а не код: ручная таблица цен в
  конфиге (`usage.prices`) и, опционально, локальный файл каталога в
  формате LiteLLM (`usage.price_catalog`). Цены применяются при
  построении сводки. В журнале хранятся только токены, поэтому смена
  прайса пересчитывает историю. Для модели без цены выводится «n/a»,
  ошибки нет.
- Сбор расхода никогда не ломает ревью: если сбор не удался, в журнал
  пишется запись без токенов с причиной, а ревью и публикация идут как
  обычно.
- Не BREAKING: новые секции конфига необязательны, без них учёт
  работает с настройками по умолчанию.

**Вне объёма** (бэклог AGENTS.md п.7): автоматический замер % лимитов
подписки (прямой `wham/usage` с токеном OpenCode v2 отвечает 401;
кандидаты — debug-лог OpenCode или Codex CLI как харнесс), отправка
записей по OTLP, строка расхода в комментарии к MR, LiteLLM-шлюз для
этапа CI, выбор модели по размеру MR, загрузка прайс-листа по сети.

## Capabilities

### New Capabilities
- `review-usage-accounting`: учёт расхода ревью. Сбор токенов прогона у
  харнесса, журнал расхода с провайдер-нейтральной схемой записи,
  ручные отметки лимитов подписки, сводка с API-эквивалентом по
  прайс-листу и оценкой доли лимитов.

### Modified Capabilities
- `local-artifact-lifecycle`: в рабочей папке появляется журнал расхода.
  Это не временный файл и не артефакт с истекающим сроком: уборка его не
  удаляет.

## Impact

- Код: `pipeline.py` (сбор расхода после harness, в том числе при
  ошибке), `harness.py` (адаптер получения расхода у харнесса), новые
  модули учёта (журнал, источник расхода, сводка и прайс-лист),
  `cli.py` (подкоманды `usage`, `quota`), `polling.py` (передача
  проекта/MR в контекст записи), `config.py` (секция `usage`),
  `housekeeping.py` (область `usage/` в раскладке рабочей папки).
- Внешние команды: дополнительно `opencode session list` и
  `opencode session export` (только чтение) после каждого прогона.
  Новых сетевых обращений нет.
- Данные: в журнал не попадают тексты промптов, отчётов и кода, только
  числа и идентификаторы.
- Документация: README (учёт расхода, команды, прайс-лист), AGENTS.md
  (дорожная карта, команды разработки).
