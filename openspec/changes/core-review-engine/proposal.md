# Proposal

## Why

Ручные эксперименты автора показали, что качество (recall) автономного код-ревью зависит в первую очередь от того, насколько свободно модель исследует репозиторий сама, и резко падает, если поведение жёстко задано заранее подготовленным pipeline (diff-центричный контекст, workflow-skill с методологией, пошаговые инструкции). Прежде чем вкладываться в GitLab-интеграцию и шедулинг (будущие отдельные change), нужен минимальный, самостоятельно проверяемый "движок" ревью: изолированный checkout MR + agentic-харнесс с полным tool-access + прямой review-промпт, который можно прогнать на реальном MR и убедиться, что recall соответствует ожиданиям, до того как система станет автоматической.

## What Changes

- Добавляется возможность подготовить изолированный `git worktree` для заданного репозитория и диапазона коммитов (base/head), с гарантированной очисткой после прогона независимо от результата
- Добавляется минимальный runtime/safety-конфиг для agentic-харнесса (без методологии ревью): запрет на выполнение кода из MR, read-only git/файловые инструменты, пути checkout/scratch, язык вывода
- Добавляется конфигурируемый прямой review-промпт (методология ревью живёт в промпте, не в системном конфиге харнесса) с подстановкой переменных запуска (путь к worktree, base/head SHA, заголовок и описание MR, путь к `AGENTS.md`/`CLAUDE.md` и `docs/` целевого репозитория, если они есть)
- Добавляется запуск выбранного agentic-харнесса в headless/non-interactive режиме с конфигурируемым провайдером модели (Claude/Codex/локальная модель) и явным параметром reasoning effort
- Добавляется механизм опциональных knowledge-skill файлов (справочник паттернов ошибок как подсказка, не ограничение), включаемых/выключаемых per-run; в этом change без содержимого самих skill-файлов
- Добавляется единая CLI-команда: вход — координаты репозитория и MR (путь/URL репозитория, base/head), выход — markdown-отчёт о ревью, сохранённый в локальный файл

Явно вне скоупа этого change (будущие отдельные change): GitLab API / `glab`-интеграция, опрос MR и фильтр по reviewer, идемпотентность/публикация отчёта в GitLab, шедулинг (Task Scheduler/cron), работа с несколькими репозиториями одновременно, auto-resolve AI-тредов, self-generating best-practices.

## Capabilities

### New Capabilities

- `mr-review-engine`: способность системы — по изолированному локальному checkout merge request'а (worktree на базе base/head коммитов), минимальному runtime-конфигу безопасности и прямому review-промпту — произвести markdown-отчёт о код-ревью через вызов конфигурируемого agentic-харнесса с заменяемым провайдером модели, включая поддержку опциональных knowledge-skill подсказок.

### Modified Capabilities

(нет — проект начинается с чистого листа, существующих capability нет)

## Impact

- Новый код: CLI entrypoint, подготовка worktree, генерация runtime-конфига харнесса, сборка review-промпта из шаблона и переменных запуска, вызов харнесса, запись markdown-отчёта
- Внешние зависимости: выбранный agentic CLI-харнесс (устанавливается отдельно, конфигурируется per-provider), git (worktree)
- Конфигурация: провайдер модели и его параметры (включая reasoning effort), путь вывода отчёта, список подключённых knowledge-skill файлов — всё конфигурируемо, без хардкода под конкретного провайдера
- Не затрагивает: GitLab, шедулинг, state/идемпотентность — они появятся в следующих change на основе этого движка
