## Найденные и исправленные баги пайплайна в процессе (не относятся к recall модели)

Первые два прогона на этом MR дали почти пустой отчёт
(`Understood — I'll operate as a Senior Software Engineer.`, без единого
вызова инструмента) — не проблема recall, а два реальных бага реализации,
вскрытых только на этом прогоне:

1. `subprocess.run(text=True)` без явной `encoding="utf-8"` на Windows
   декодировал UTF-8-вывод OpenCode как cp1252 (мохибейк в тире/кавычках).
2. **Критичный**: `opencode` на Windows резолвится в `opencode.CMD`
   (npm-шим), исполняемый только через `cmd.exe`, который разбирает
   командную строку построчно — многострочный промпт, переданный как
   позиционный аргумент (`"{prompt}"`), обрывался на первой строке. Модель
   честно отвечала на то немногое, что получила, без единого tool call,
   процесс завершался с кодом 0 без видимой ошибки. Воспроизведено
   напрямую, исправлено переходом на `--file {prompt_file}` (вложение,
   минует построчный парсинг `cmd.exe`).

Оба фикса закоммичены (`6e26ac2`, `3dd8920`) и покрыты обновлённым
`AGENTS.md`/README/докстрингами. **Это значимая находка сама по себе**:
движок в принципе может "тихо" деградировать до нулевого recall на
конкретной ОС без единой ошибки в коде выхода — сигнал для будущих
изменений: стоит валидировать непустоту/длину отчёта как минимальную
проверку на уровне оркестратора (не сделано в этом change, см. "Не
доделано" ниже).

## Результат третьего прогона (после обоих фиксов)

Отчёт: `reports/review-1790891687-14c86725.md`. 5 находок:

- 3 × Major (повторная отправка формы через "Вперёд"/дублирующий POST;
  фоновый silent-refresh уводит на страницу ошибки при сетевом сбое;
  race condition в `reset()` пагинации между старым и новым запросом)
- 2 × Minor (утечка старого ключа кэша при смене URL пагинации;
  отсутствие интеграционных/e2e-тестов нового флоу)

Каждая находка — с точным файлом и номером строк, объяснением сценария
воспроизведения и минимальным исправлением (включая код для гонки в
пагинации). Качественно соответствует описанному в `AGENTS.md` §3 режиму
"свободного исследования": агент сам читал файлы, сопоставлял потоки
данных между виджетами, без подготовленного diff/brief.

## Сравнение со списком находок A–M из исходного 3-недельного исследования

**Не выполнено в этом прогоне.** Исходный handoff-документ с перечнем
A–M находок был загружен в предыдущей сессии в другом (временном,
sandboxed) окружении и недоступен на текущей рабочей машине — файл не
найден локально. Прямое попунктное сопоставление recall/overlap с
эталоном, как требовала задача 8.1, физически не из чего посчитать прямо
сейчас.

Качественная, но не количественная оценка: структура и глубина находок
(race conditions, повторная отправка через history navigation, тихий
отказ фонового запроса) соответствуют уровню детализации, который в
исходном исследовании ассоциировался с лучшими ("9 находок"/"7 находок")
прогонами свободного исследования, а не с ухудшенными skill-ограниченными
(2-3 находки) — но это впечатление, не измеренное число.

## Решение (задача 8.2): GO, с одной оговоркой

Двигаемся дальше к Change 2 (`gitlab-polling-and-publishing`) **как есть**,
без доработки промпта/конфига прямо сейчас:

- Движок на реальном бенчмарке и реальном облачном провайдере дал
  содержательный, разнообразный по типам находок отчёт — ядро архитектуры
  (free exploration + denylist safety + generated per-run config) работает
  на практике, не только в юнит-тестах.
- Оба найденных в процессе бага — артефакты транспорта (кодировка,
  Windows argv), не архитектуры ревью-движка; они закрыты и не требуют
  пересмотра решений из `design.md`.
- Количественного сравнения с A–M нет, но это пробел в данных
  (недоступен исходный документ на этой машине), а не сигнал о качестве
  движка — не повод блокировать Change 2.

## Не доделано / явные пробелы на момент закрытия change

- **Количественное сравнение с находками A–M не выполнено** — исходный
  handoff-документ недоступен на этой машине. Если он понадобится позже
  (например, для A/B сравнения с knowledge-skill слоем), его нужно будет
  заново найти/загрузить.
- Проверено ровно **на одном** реальном MR с одним провайдером
  (`openai/gpt-5.6-terra#medium`). Swap провайдера (Claude/Codex/
  локальная модель) на этом MR не перепроверялся вживую — только
  юнит-тестами с стаб-харнессом (задача 5.2).
- Нет автоматической проверки "отчёт не подозрительно пустой" — баг с
  обрезанным промптом был обнаружен только потому, что отчёт прочитал
  человек. Стоит рассмотреть как пункт бэклога для Change 2/3
  (минимальная эвристика вроде "report length / tool-call count").
- `denied_bash_patterns` — denylist, не allowlist (см. `AGENTS.md` §4);
  известное ограничение, не новое для этого прогона, но стоит иметь в
  виду при расширении на backend-репозитории с другим набором
  интерпретаторов/команд.
