# Proposal

## Why

Сейчас промпт ревью целиком задан в коде. Методология (роль, что проверять,
SEV, язык вывода) лежит строкой в `prompt.py`. Динамические секции
(инструкции целевого репозитория, docs, skills) и их формулировки собирают
Python-функции. Списки файлов инструкций (`AGENTS.md` → `CLAUDE.md` →
`.github/copilot-instructions.md`) и папок документации тоже зашиты в коде.
review-agent должен ревьюить не только фронтенд, но и бэкенд и другие стеки,
а для этого методологию и подсказки о контексте нужно менять для каждого
проекта без правки кода. При этом текущий промпт — проверенный baseline
(AGENTS.md п.3), и по умолчанию он должен остаться прежним до байта.

## What Changes

- Промпт становится Jinja2-шаблоном. Текущий текст переносится без изменений
  в файл встроенного шаблона `builtin/default.md.j2` внутри пакета, разбитый
  на блоки (`{% block %}`). Формулировки динамических секций и условия их
  вывода тоже переходят в шаблон, и в Python не остаётся кода, который
  формирует текст промпта.
- Новая секция конфига `prompt:` с ключами `template` (путь к файлу шаблона,
  `null` — встроенный), `instruction_files` и `docs_dirs` (кандидаты внутри
  ревьюируемого репозитория; берётся первый найденный). Значения по
  умолчанию — текущие. Текст промпта в конфиг не пишется, только путь к
  файлу.
- Каждый проект может задать свою секцию `prompt:`. Переопределение идёт **по
  ключам**: заданный ключ заменяет значение уровнем ниже (глобальное →
  встроенное), незаданный наследуется. Список заменяется целиком. `skills` у
  проекта уже переопределяется и остаётся на своём месте.
- Свой шаблон может заменить промпт целиком или наследовать встроенный
  (`{% extends "builtin/default.md.j2" %}`) и переопределить отдельные блоки.
  Шаблон берётся только из конфига оркестратора и никогда не берётся из
  ревьюируемого репозитория.
- Пути в `prompt.template` и `skills` при загрузке конфига превращаются в
  абсолютные (от текущей папки процесса, как и раньше), поэтому в промпт
  попадает рабочий путь к skill независимо от папки агента. Чтение самих
  skill-файлов агентом этим не чинится: живая проверка показала, что
  OpenCode отклоняет чтение вне worktree (`external_directory`). Это
  известное ограничение, вне scope этого change, — в бэклоге AGENTS.md
  п.7 как отдельная задача.
- Проверка шаблонов перед работой. **Ошибки**: файл не найден, синтаксическая
  ошибка, неизвестная переменная или атрибут. **Предупреждения**: шаблон не
  использует ожидаемую переменную, файл skill не найден. Все замечания по
  всем проверяемым шаблонам собираются за один раз и выводятся одним
  списком. При ошибках работа не начинается. Если есть только
  предупреждения, в интерактивном режиме задаётся один вопрос «Продолжить?»,
  а в `poll --all` и без консоли предупреждения пишутся в лог и работа
  продолжается. Новых флагов нет.
- Новая подкоманда `review-agent prompt-check [--config] [--project PATH]
  [--template FILE] [--show]`. Она проверяет шаблоны из конфига (все проекты,
  включая выключенные) или отдельный файл и по `--show` печатает промпт,
  отрендеренный с тестовыми значениями. Коды выхода: 0 — замечаний нет, 1 —
  только предупреждения, 2 — ошибки.
- Журнал расхода дополнительно записывает шаблон промпта прогона (путь или
  `builtin/default.md.j2`) и sha256 его файла, чтобы различать прогоны с
  разными промптами при A/B.
- Новая зависимость: `Jinja2>=3.1`.

## Capabilities

### New Capabilities

- `review-prompt-templates`: шаблон промпта (встроенный и свой), переменные
  шаблона, проверка шаблонов (ошибки и предупреждения, сбор за один раз,
  поведение в интерактиве и в автоматическом режиме), команда
  `prompt-check`.

### Modified Capabilities

- `mr-review-engine`: методология по-прежнему живёт только в промпте, но
  теперь задаётся шаблоном, встроенный шаблон воспроизводит текущий промпт;
  кандидаты файла инструкций и папки docs берутся из настроек, а не из
  кода.
- `project-review-settings`: проект может переопределить по ключам
  `prompt.template`, `prompt.instruction_files`, `prompt.docs_dirs` поверх
  глобальных значений и встроенных значений по умолчанию.
- `review-usage-accounting`: запись ревью содержит шаблон промпта и его
  sha256.

## Impact

- Код: `prompt.py` (рендер Jinja2, проверка шаблонов, поиск кандидатов по
  спискам), новый `src/review_agent/prompts/default.md.j2`, `config.py`
  (секция `prompt`, переопределение проекта по ключам, абсолютные пути),
  `pipeline.py` (передача настроек промпта и их запись в журнал),
  `polling.py` и `cli.py` (проверка перед работой, вопрос, подкоманда
  `prompt-check`), `usage_ledger.py` (новые поля записи), `pyproject.toml`
  (зависимость и package data).
- Зависимости: `Jinja2>=3.1` (Pallets, де-факто стандарт шаблонов в Python).
- Документация по AGENTS.md п.11:
  - `README.md` — подкоманда и флаги `prompt-check`, коды выхода, ключи
    `prompt` в примере конфига, зависимость Jinja2;
  - `docs/configuration.md` — секция `prompt`, переопределение по ключам,
    абсолютные пути `skills`;
  - новый `docs/prompt.md` — шаблоны, переменные, наследование блоков,
    проверка и `prompt-check`;
  - `docs/polling.md` — проверка шаблонов в начале прохода;
  - `docs/usage-accounting.md` — новые поля журнала;
  - `docs/architecture.md` — шаблон в потоке прогона;
  - `docs/decisions.md` — почему Jinja2, почему по ключам, почему шаблон не
    из worktree;
  - `docs/troubleshooting.md` — ошибки и предупреждения шаблона;
  - `config.example.yaml` — секция `prompt` и пример проекта;
  - `AGENTS.md` п.4 (промпт задаётся шаблоном), п.7 (бэклог: баг чтения
    skill-файлов агентом, denylist на проект), п.10 (модуль, шаблон
    пакета, capability).
- `openspec/config.yaml` обновляется при архивации.
