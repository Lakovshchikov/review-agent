# Validation notes — configurable-review-prompt

Проверки 2026-10-04 на Windows, OpenCode 2.0.21, боевой GitLab
(`git.platops.ru`). Ревью с моделью — только в `--dry-run`, в GitLab ничего
не публиковалось.

## Найденный баг (вне scope): skill-файлы не читаются агентом

`harness-stderr.log` прогона `!11`:

```
! permission requested: external_directory (E:/.../.review-agent/prompt-test/*); auto-rejecting
✗ Read E:/.../prompt-test/skill.md failed
Error: This non-interactive run cannot ask the user for permission, so the request was rejected.
```

У OpenCode 2.0.21 чтение вне рабочей папки — разрешение
`external_directory` со значением по умолчанию `ask`; неинтерактивный
прогон отклоняет запрос. Skill-файлы всегда вне worktree, значит skills не
доходили до агента с change 1 (раньше не замечено: в боевом конфиге
`skills: []`). Решение пользователя: не чинить в этом change, а
пересмотреть подход к skill'ам отдельной задачей. Зафиксировано как
известное ограничение в `docs/configuration.md#skills`,
`docs/troubleshooting.md`, `docs/prompt.md`, `config.example.yaml` и в
бэклоге AGENTS.md п.7 (с кандидатами исправления).

## Ручной режим (выполнил агент)

Копия боевого конфига: глобальный шаблон без `base_sha`, вместо OpenCode в
`harness.command` — Python-заглушка, которая возвращает отчёт с первой
строкой промпта. Настоящие: проверка шаблона, lock, worktree на
`b2c/front-shopping` (бенчмарк `!544`), рендер промпта, запись отчёта.

| Ветка | Как | Результат |
|---|---|---|
| Без консоли | `cmd /c "review-agent --repo … < NUL"`, полностью вживую | предупреждение в stderr, вопроса нет, отчёт записан, код 0, `tmp/` пуст |
| Консоль, ответ `n` | `cli.main` с подменённым определением консоли и вводом | один вопрос, «Ревью отменено…», код 2, отчёта нет |
| Консоль, ответ `y` | то же | один вопрос о шаблоне, затем обычные вопросы о квоте, отчёт записан, код 0 |

Настоящая консоль Windows агенту недоступна, поэтому ветки с вопросом
проверены с подменой `stdin_is_interactive`. Само определение консоли
проверено вживую пользователем в интерактивном `poll` (та же функция).

Наблюдение (не связано с change): рабочая папка с лишним уровнем
вложенности (`<work_dir>\work	mp\<run>\worktree`) не помещается в
MAX_PATH для длинных путей `b2c/front-shopping` (`Filename too long`).
С обычной раскладкой `.review-agent	mp\<run>\worktree` в папке проекта
всё работает.
